PC-1403 CASSETTE ENDING TEST — COMPILED EXPERIMENTAL FIRMWARE
English translation of the delivery notes, 6 October 2026.

Observation: in the V5 firmware, the final byte includes two trailing bits,
then the firmware emits two additional bits, giving approximately 8 ms of
tone after the last data bit. This experiment adds another 100 bits of
1 tone, approximately 200 ms, after the final byte. It changes neither the
TAP file, the pulses for each bit, nor the 2-second leader. This is not a
silent gap: the interface maintains an idle tone during this period.
The hypothesis of an end-of-signal problem still needs to be checked on a
real PC-1403.

SharpTailTest.hex is the compiled firmware for ATmega328P 5 V / 16 MHz.
The SharpTailTest directory contains the variant sources. SharpOriginalV5
contains the original sources, and ProMiniSync2s_original.hex is the
previously supplied original V5 file, for restoring the initial state.

TEST WITH ARDUINO IDE INSTALLED ON THE MAC
1. Back up the Sharp program. Disconnect the Sharp connector from the
   Pro Mini and close SharpManager before uploading.
2. Open SharpTailTest/SharpTailTest.ino in Arduino IDE.
3. Select Arduino Pro or Pro Mini, ATmega328P 5 V / 16 MHz and the
   FTDI /dev/cu.usbserial-... port; upload as with the previous firmware.
4. Reconnect the Sharp and launch SharpManager V3 or V4. Its identification
   line should end with “synchro 2s - fin 200ms”.
5. Using the same PROGRAM.tap with the “pause 50 ms” option disabled,
   compare several CLOAD attempts with the original V5 firmware results.

ROLLBACK: open SharpOriginalV5/SharpOriginalV5.ino and upload it with the
same settings. The identification string returns to “synchro 2s”.

The variant was built with avr-gcc 7.3 and Arduino AVR core 1.8.6.
It uses 7884 flash bytes and 391 static SRAM bytes.
The .hex file is provided for upload with a compatible AVR tool. On the
Mac, the simplest procedure remains opening the .ino in Arduino IDE and
uploading it. The variant has not been tested on a physical Sharp.
