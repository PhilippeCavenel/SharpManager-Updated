SHARPMANAGER BASIC PC-1403 — V5
Version 1.0.5-basic-pc1403-v5 — 4 October 2026
English translation of the delivery notes, 6 October 2026.

WHAT'S NEW
- Pro Mini 5 V / 16 MHz firmware: cassette leader extended from 250 to
  1000 HIGH bits, approximately 0.5 to 2 seconds before the first byte.
  This is a synchronization signal, not silence. The frequency and data
  encoding remain the same as in the original version.
- Windows waits up to 8 seconds for a CLOAD block acknowledgment.
- After CSAVE, choose between readable BASIC (.bas, UTF-8) and the raw
  cassette file (.tap). BASIC decoding is automatic for the PC-1403.
The cause of ERROR 8 remains uncertain: the longer leader is an experiment.
Installing Windows V5 alone does not change the signal sent by the Arduino.

WINDOWS INSTALLATION
1. Close any other SharpManager applications.
2. Extract the entire archive into a new directory; do not mix DLL versions.
3. Run SharpManagerBasicPc1403.exe and check for BASIC PC-1403 V5 in its title.
   Keep the PocketTools directory alongside the executable.
The .NET 10 Desktop runtime for Windows x64 is required, as before.
Preferences are separate from the official application and from V4:
%LOCALAPPDATA%\SharpManagerBasicPc1403\V5\settings.json
Select the COM port of your FTDI cable again.

INSTALL THE 2-SECOND SYNCHRONIZATION FIRMWARE
1. Disconnect the Sharp before uploading; connect the Pro Mini to the usual
   FTDI cable.
2. With SharpManager disconnected, open Upload Firmware (the Arduino button).
3. Select the COM port and one of the two added profiles:
   Pro Mini 5 V/16 MHz — synchro 2 s (57600) if the previous working profile
   was Nano R3 (Old Bootloader), or the (115200) profile if it was Nano R3.
   These speeds apply to the bootloader; normal communication stays at 115200.
4. Click Upload Firmware, wait for success, then close the window.
5. Click Connect: the log should show Arduino Driver 1.3 - synchro 2s.
Uploading replaces the Arduino program, not its bootloader.
The existing D2-to-D9 wiring and resistors remain usable.
Firmware/ProMiniSync2s.hex is also included, without the bootloader.
For Arduino IDE, open Firmware/Arduino/Arduino.ino, select Arduino Pro
or Pro Mini and ATmega328P (5V, 16MHz), then upload.
Other profiles retain their original firmware. To restore the 0.5-second
leader, upload Nano R3 (Old Bootloader) or Nano R3, according to the profile
that previously worked with your Pro Mini.

SEND A BASIC PROGRAM
1. Connect the interface to the idle Sharp in RUN mode, then click Connect
   in Windows.
2. Select Envoyer BASIC… (Send BASIC) and choose a numbered .bas source file.
3. When prompted, enter CLOAD and press ENTER on the Sharp in RUN mode.
4. Click OK in Windows, wait for loading to finish, then enter RUN.
The program currently on the Sharp is replaced: keep a backup.
Conversion uses only internal temporary files.
You can still send .tap files using Send Tape File.
For comparison, load CHRONO.bas five times without closing SharpManager,
then repeat after Disconnect / Connect. Record failures and retain the log.

SAVE CSAVE AS BASIC
1. In the connected SharpManager application, choose File > Recevoir / CSAVE….
2. On the Sharp in RUN mode, enter CSAVE and press ENTER.
3. Once reception finishes, choose Programme BASIC (*.bas) and save the file.
4. Read the .bas file in a Windows editor or send it again with Envoyer BASIC….
Choose Cassette Sharp (*.tap) to retain the raw data instead.
If decoding fails, another dialog lets you save the same data as .tap without
running CSAVE again. Do not cancel that dialog if you want to retain the data.
Non-BASIC data and protected programs must remain in .tap format.
The .bas file restores the program; original formatting and the cassette
filename are not necessarily preserved.

VALIDATION AND LIMITATIONS
- Windows x64 application built; simulated transfers from 41 to 250 bytes,
  reconnections, CSAVE, exclusive reader access and an ACK delayed by 6 seconds.
- BONJOUR and CHRONO decoded and re-encoded: identical program data.
  Rejection of non-BASIC formats, invalid checksums and cancellation tested.
- Preferences: isolation, saving, reloading and corrupt-file handling tested.
- Firmware built with Arduino AVR core 1.8.6 and avr-gcc 7.3.0 Arduino7:
  6016 flash bytes out of 30720 available; 366 static RAM bytes out of 2048.
  Warnings inherited from the Arduino code concern shifts in WaitReadInt,
  repeated default arguments and a variable in a case statement. The related
  disk functions were not modified for this synchronization experiment.
- Actual Tape::Load code tested by measuring timing calls: a nominal
  2 000 000 microsecond leader, followed by the usual bytes and trailing bits.
These tests reproduce neither the electronics, the Sharp ROM, nor actual use
of the Windows interface. The physical setup and the effect on ERROR 8 still
need to be validated.

SOURCE CODE AND BUILDING
BuildWindowsBasic.bat: .NET 10 SDK; builds Windows and the common engine.
BuildProMiniFirmware.py: builds the HEX file for ATmega328P / 16 MHz.
Arduino sources, tests and results are included in the Sources archive.
The V4 communication fixes are retained: one serial reader, waiting for the
old reader during reconnection, and no NAK after a valid packet.
This version does not reprogram the FTDI or add an automatic RTS reset.
