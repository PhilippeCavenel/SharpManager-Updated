RING BUFFER FIX — SHARP PC-1403
English translation of the delivery notes, 6 October 2026.

This variant fixes the problem observed with queen's quest.bas, a 5717-byte
TAP: an error at block 5, bytes 257–320. In the previous firmware, an ACK
could allow the next block to be sent while the 256-byte ring buffer was
nearly full. The USB serial interface sends 64 bytes very quickly, and the
hardware RX buffer cannot wait while the Sharp consumes them at approximately
26 ms per byte.

Each block ACK, except for the final block, is now sent only when at least
64 free slots remain in the ring buffer. Timer1 continues generating the
cassette signal while waiting. SharpManager macOS V5.2 already waits up to
20 seconds for an ACK and still recognizes the identification string
“synchro 2s - flux continu V5 - garde 64”.

1. Close SharpManager and disconnect the Sharp from the Pro Mini before
   flashing.
2. Open SharpStreamSafe/SharpStreamSafe.ino in Arduino IDE.
3. Select Arduino Pro or Pro Mini, ATmega328P 5 V / 16 MHz and the FTDI port.
4. Upload, reconnect the Sharp and restart SharpManager V5.2.
5. Check for “garde 64” in the connection line; retry the TAP supplied in
   the SharpManager V5.2 archive.

SharpStreamSafe.hex is the AVR build of this variant. The SharpStreamPrevious
directory contains the previous firmware sources, which loaded small
programs successfully, so that this state can be restored if needed.
Hardware tests with the larger program remain to be performed.

Flash: 8220 bytes; static RAM: 682 bytes on ATmega328P.

UPDATE - 8 OCTOBER 2026
Philippe Cavenel reports successful use of his physical FTDI / Pro Mini /
PC-1403 setup from macOS, Ubuntu and Windows. Keep the working firmware
when changing host platform. No new firmware was produced by this update.
